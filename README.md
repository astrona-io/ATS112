# ATS112 — Fundamentals, Architecture & CLI Operations (OpenBao)

Course material for the **Fundamentals, Architecture & CLI Operations** domain
of the Astrona OpenBao training path ([ATP022](https://github.com/astrona-io/ATP022)),
which is **10% of the path**. Written for **OpenBao v2.7.1**.

> **Status: draft, not yet run.** Every page, playground and lab was written
> from the OpenBao v2.7.1 documentation and source. None has been started on
> a cluster, and no lab has passed `astrona test` yet. See `CLAUDE.md`.

The course opens with an Introduction in `sections/intro/` (welcome, machine setup,
how the course is made). Everything else lives under `sections/`. Each section
contains:

- **Modules** — a reading chapter split into a short landing page, ordered
  deep-dive parts and a summary page, a throwaway **playground** to explore in,
  and a graded **lab** placed right after the part it tests.
- **A capstone** — one larger graded lab combining that section's modules into a
  single scenario with several independent faults.

Section 020 shows the configuration a server runs with and how the Helm chart
applies it. Section 030 is the operator's daily toolkit, from `bao operator
init` to rotating keys and retiring the root token.

## The lab environment

Every playground and lab is a **kind** cluster with OpenBao v2.7.1 installed by
the `openbao` Helm chart 0.30.4 (one pod `openbao-0`, Integrated Storage on a
PersistentVolumeClaim, no TLS — lab-only), a `tester` pod with `curl` and `jq`,
and Helm 3.22.1 plus the `bao` CLI 2.7.1 installed on the machine. OpenBao
answers at `http://openbao.localtest.me:8200` everywhere: through
`kubectl -n openbao port-forward svc/openbao 8200:8200` on the machine, and a
CoreDNS rewrite inside the cluster.

`INIT_MODE` in the install script decides the starting state: `sealed` (not
initialized), or `unsealed` (initialized with one lab-only key share kept in
the Secret `openbao-init`). Section 010 environments add a step that
initializes with five shares (Secret `openbao-shares`) and seals again.

Shared plumbing (config files, author READMEs, prerequisites, install and
testing scripts, and the helper block in every script) is generated by a
script kept outside the repository. When you change a shared helper, change it
in every environment.

## Running a playground

```bash
astrona run --git ssh://git@github.com/astrona-io/ATS112.git -c sections/<section>/<module>/playground
astrona destroy <name>
```

## Running a lab

Labs and capstones are graded. Read `question.md`, do the work, and submit:

```bash
astrona run --git ssh://git@github.com/astrona-io/ATS112.git -c sections/<section>/<module>/labs/lab-01
astrona submit -c sections/<section>/<module>/labs/lab-01
astrona destroy <name>
```

Each lab grades the **final state** with independent checks, and several of
them reject the plausible-but-wrong fix (initializing the server again,
running a development server, keeping the root token).
